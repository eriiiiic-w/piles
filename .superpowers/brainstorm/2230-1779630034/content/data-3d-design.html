SQLite 数据模型 & 3D 交互详细设计

最后两个设计环节：数据库表结构 + 3D 场景交互功能清单

SQLite 表结构
geo_layers          勘探孔分层数据
  id, hole_id, x, y, layer_name
  top_elev, thickness, bottom_elev

piles                 桩基数据
  id, pile_no, x, y, diameter
  pile_type, top_elev

predictions          预测结果缓存
  id, pile_no, layer_name
  top_elev_pred, bottom_elev_pred
  method, created_at

measured             实测数据
  id, pile_no, layer_name
  measured_elev, actual_depth
  recorded_at

settings             系统设置
  id, key, value
  (support_layer, support_depth
   depth_type, warning_threshold
   alarm_threshold, interp_method
   pile_top_elev)

soil_params          土层承载力参数
  id, layer_name, qsik, qpk

operation_logs      操作日志
  id, action, detail, created_at
与旧 JSON 的对照
旧 JSON 字段新 SQLite 表
geo_data[]→ geo_layers
pile_data[]→ piles
measured_data{}→ measured
support_layer等→ settings
(预测结果)→ predictions (新增)
(承载力参数)→ soil_params (新增)
(无)→ operation_logs (新增)

predictions 表是新增的预测结果缓存，避免每次页面请求都重复计算。实测数据不再写回 geo_layers（修复报告中指出的数据污染问题）。
